## Examples

Chassis includes a bunch of predefined buttons components, each serving its own semantic purpose. Buttons show what action will happen when the user clicks or touches it. Chassis buttons are used to initialize operations, both in the background or foreground of an experience.

## Disable text wrapping

If you don't want the button text to wrap, you can add the `.text-nowrap` className to the `<CxButton>`. In Sass, you can set `$btn-white-space: nowrap` to disable text wrapping for each button.

## Button components

The `<CxButton>` component are designed for `<button>` , `<a>` or `<input>` elements (though some browsers may apply a slightly different rendering).

If you're using `<CxButton>` component as `<a>` elements that are used to trigger functionality ex. collapsing content, these links should be given a `role="button"` to adequately communicate their meaning to assistive technologies such as screen readers.

<Example>
  <CxButton component="a" context="primary" href="#" role="button">
    Link
  </CxButton>
  <CxButton type="submit" context="primary">
    Button
  </CxButton>
  <CxButton component="input" type="button" context="primary" value="Input" />
  <CxButton component="input" type="submit" context="primary" value="Submit" />
  <CxButton component="input" type="reset" context="primary" value="Reset" />
</Example>

```jsx
<CxButton component="a" context="primary" href="#" role="button">Link</CxButton>
<CxButton type="submit" context="primary">Button</CxButton>
<CxButton component="input" type="button" context="primary" value="Input"/>
<CxButton component="input" type="submit" context="primary" value="Submit"/>
<CxButton component="input" type="reset" context="primary" value="Reset"/>
```

## Disabled state

Add the `disabled` boolean prop to any `<CxButton>` component to make buttons look inactive. Disabled button has `pointer-events: none` applied to, disabling hover and active states from triggering.

<Example>
  <CxButton context="primary" size="large" disabled>
    Primary button
  </CxButton>
  <CxButton context="secondary" size="large" disabled>
    Button
  </CxButton>
</Example>

```jsx
<CxButton context="primary" size="large" disabled>Primary button</CxButton>
<CxButton context="secondary" size="large" disabled>Button</CxButton>
```

Disabled buttons using the `<a>` component act a little different:

`<a>`s don't support the `disabled` attribute, so Chassis has to add `.disabled` className to make buttons look inactive. Chassis also has to add to the disabled button component `aria-disabled="true"` attribute to show the state of the component to assistive technologies.

<Example>
  <CxButton component="a" href="#" context="primary" size="large" disabled>
    Primary link
  </CxButton>
  <CxButton component="a" href="#" context="secondary" size="large" disabled>
    Link
  </CxButton>
</Example>

```jsx
<CxButton component="a" href="#" context="primary" size="large" disabled>Primary link</CxButton>
<CxButton component="a" href="#" context="secondary" size="large" disabled>Link</CxButton>
```

The `.disabled` class uses `pointer-events: none` to try to disable the link functionality of `<a>`s, but that CSS property is not yet standardized. Besides, even in browsers that do support `pointer-events: none`, keyboard navigation remains unaffected, meaning that sighted keyboard users and users of assistive technologies will still be able to activate these links. So to be safe, we automatically add a `tabindex="-1"` attribute on disabled links (to prevent them from receiving keyboard focus) and use custom JavaScript to disable their functionality.

## Block buttons

Create buttons that span the full width of a parent—by using utilities.

<Example>
  <div className="d-grid gap-2">
    <CxButton context="primary">Button</CxButton>
    <CxButton context="primary">Button</CxButton>
  </div>
</Example>

```jsx
<div className="d-grid gap-2">
  <CxButton context="primary">Button</CxButton>
  <CxButton context="primary">Button</CxButton>
</div>
```

Here we create a responsive variation, starting with vertically stacked buttons until the `md` breakpoint, where `.medium:d-block` replaces the `.d-grid` class, thus nullifying the `gap-2` utility. Resize your browser to see them change.

<Example>
  <div className="d-grid gap-2 medium:d-block">
    <CxButton context="primary">Button</CxButton>
    <CxButton context="primary">Button</CxButton>
  </div>
</Example>

```jsx
<div className="d-grid gap-2 medium:d-block">
  <CxButton context="primary">Button</CxButton>
  <CxButton context="primary">Button</CxButton>
</div>
```

You can adjust the width of your block buttons with grid column width classes. For example, for a half-width "block button", use `.col-6`. Center it horizontally with `.mx-auto`, too.

<Example>
  <div className="d-grid gap-2 col-6 mx-auto">
    <CxButton context="primary">Button</CxButton>
    <CxButton context="primary">Button</CxButton>
  </div>
</Example>

```jsx
<div className="d-grid gap-2 col-6 mx-auto">
  <CxButton context="primary">Button</CxButton>
  <CxButton context="primary">Button</CxButton>
</div>
```

Additional utilities can be used to adjust the alignment of buttons when horizontal. Here we've taken our previous responsive example and added some flex utilities and a margin utility on the button to right align the buttons when they're no longer stacked.

<Example>
  <div className="d-grid gap-2 medium:d-flex medium:justify-content-end">
    <CxButton context="primary" className="medium:me-2">
      Button
    </CxButton>
    <CxButton context="primary">Button</CxButton>
  </div>
</Example>

```jsx
<div className="d-grid gap-2 medium:d-flex medium:justify-content-end">
  <CxButton context="primary" className="medium:me-2">
    Button
  </CxButton>
  <CxButton context="primary">Button</CxButton>
</div>
```
