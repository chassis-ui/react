## Examples

`<Modal>` composes `<ModalHeader>`, `<ModalBody>`, and `<ModalFooter>` sub-components around its dialog content.

### Modal components

This static example is rendered with `open`, so it is open from the first paint as a non-modal dialog, and disables the backdrop and keyboard dismissal so it stays open for illustration. It includes a modal header, a modal body (required for `padding`), and an optional modal footer. Include a modal header with a dismiss action whenever possible, or provide another explicit dismiss action.

<Example customMarkup={`<Modal backdrop={false} keyboard={false} open>
    <ModalHeader>
      <ModalTitle>Modal title</ModalTitle>
    </ModalHeader>
    <ModalBody>Modal body text goes here.</ModalBody>
    <ModalFooter>
      <Button color="secondary">Close</Button>
      <Button color="primary">Save changes</Button>
    </ModalFooter>
  </Modal>`}>

</Example>

### Live demo

Toggling the button below opens a working modal that slides down and fades in from the top of the page.

`visible` opens and closes the modal. A close request (the Escape key, a backdrop click, a close button) fires `onClose`, and `onVisibleChange(false)` beside it, so `visible={open} onVisibleChange={setOpen}` works as well as `onClose={() => setOpen(false)}`. With `defaultVisible` instead, the modal is open at first and closes itself.

## Accessibility

The `<dialog>` element carries an implicit `role="dialog"` when opened with `showModal()`. `<Modal>` generates an id and wires it to `aria-labelledby` automatically — render a `<ModalTitle>` anywhere inside and it picks up that id, giving the modal an accessible name with no manual wiring. Pass an explicit `id` to `<ModalTitle>` to opt out, or set your own `aria-labelledby` on `<Modal>` to point elsewhere.

Focus moves to the modal on open — to the first element with `data-autofocus` (or an `autofocus` attribute in server-rendered HTML), otherwise to the modal itself. React's `autoFocus` prop isn't enough in a page rendered in the browser: React writes no `autofocus` attribute there. After the modal closes, focus returns to whichever element was focused when it opened.
