## Colors

  <ColorExample client:load />
</Example>

<Callout type="info">
  Color alone doesn't convey meaning to assistive technology. Pair a context color with visible
  text describing the action, or add hidden text via the `.visually-hidden` class when the color
  itself carries information.
</Callout>

## Style variants

Layer `variant` on top of `color` to change a button's fill instead of its palette.

### Outline

Set `variant="outline"` for a transparent background with a colored border and text — a
lower-emphasis alternative to a solid button in the same color.

<Example class="d-flex flex-wrap gap-sm">
  <OutlineExample client:load />
</Example>

<Callout type="info">
  Some outline colors use a light foreground meant for a dark background — check contrast before
  using them on a light surface.
</Callout>

### Smooth

Set `variant="smooth"` for a subdued, tinted background in the button's color, softer than the
default solid fill.

<Example class="d-flex flex-wrap gap-sm">
  <SmoothExample client:load />
</Example>

### Link

Set `variant="link"` to make a button look and behave like a hyperlink while keeping its `color`
and click behavior — a lower-emphasis action inside a toolbar or form. `variant="link"` is a
button-specific style, not a context color: pass it alongside `color`, not instead of it.

<Example class="d-flex flex-wrap gap-sm">
  <LinkExample client:load />
</Example>

## Root element

Set `component` to render `<Button>` as a different element — `"a"` for navigation, `"input"` for
legacy form markup, or any custom component. `href` implies `component="a"` automatically, so
setting `href` alone is enough for a link button.

<Example class="d-flex flex-wrap gap-sm">
  <ComponentExample client:load />
</Example>

A button rendered as `<a>` for something other than navigation — collapsing content, for example —
needs an explicit `role="button"`; Chassis doesn't add it automatically, since not every
`component="a"` usage is a non-navigation action. `type` only affects `<button>` and `<input>`; it
has no effect when rendered as `<a>`.

A plain tag other than `"button"`, `"a"`, or `"input"` (for example `"span"`) gets keyboard
activation, focus handling, and `role="button"` synthesized automatically, matching native button
behavior. A component reference (for example a router's `Link`) doesn't: it's trusted to bring its
own semantics, since stamping `role="button"` onto the `<a>` it renders would be wrong.

### Router links with `asChild`

To render a router's link component with button styling, pass it as the child with `asChild`,
instead of passing it by reference to `component`. The button's classes, props and ref are merged
onto the child element, and the router link still handles navigation:

```tsx
import Link from 'next/link'
import { Button } from '@chassis-ui/react/button'

<Button asChild variant="outline">
  <Link href="/login">Log in</Link>
</Button>
```

This form also works from a React Server Component. `component={Link}` there fails to build with
"Functions cannot be passed directly to Client Components", because a component reference is a
function and can't cross the server-to-client boundary. A JSX element can. See
[Server-side rendering]([[docsref:/getting-started/ssr#polymorphic-components]]).

## Pressed state

Set `pressed` to mark a toggle-style button as active — e.g. a formatting toolbar button that
stays highlighted while its feature is on. It applies the `.active` class and sets `aria-pressed`,
so assistive technology announces "button, pressed" instead of treating the button as a navigation
link.

<Example>
  <PressedExample client:load />
</Example>

## Disabled state

Set `disabled` to make a button non-interactive. A native `<button>` or `<input>` uses the real
`disabled` attribute, which blocks keyboard and pointer interaction on its own.

<Example>
  <DisabledExample client:load />
</Example>

`<a>` has no `disabled` attribute, so a disabled link button sets `aria-disabled="true"` and
`tabindex="-1"` instead, and blocks its own click handler and navigation.

<Example>
  <DisabledLinkExample client:load />
</Example>

## Scope

**No automatic `role="button"` on non-navigation links.** Rendering `<Button>` with
`component="a"` for an action rather than navigation (see [Root element](#root-element)) still
needs an explicit `role="button"` — Chassis can't distinguish the two cases from `href` alone.
