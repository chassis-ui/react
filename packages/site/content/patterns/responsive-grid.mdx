## Overview

The grid system lays content out on twelve columns with [`<Grid>`]([[docsref:/components/grid]])
and `<GridItem>`. It is built on
[CSS Grid](https://developer.mozilla.org/en-US/docs/Web/CSS/CSS_grid_layout) and follows the
viewport through six breakpoints.

<Example class="cxd-example-grid text-center">
  <ThreeColumnsExample client:load />
</Example>

Three items of four tracks each make three equal columns at every viewport width. The
[`<Container>`]([[docsref:/components/container]]) around them centers the grid in the page; a grid
doesn't need one to work.

  This guide used to describe the flexbox grid of `<Row>` and `<Col>`, which is deprecated. See
  [Migrating from Row/Col]([[docsref:/components/grid#migrating-from-rowcol]]) to move a layout
  over.
</Callout>

## Layout primitives

The grid isn't the only layout tool, and two others cover what it isn't the best fit for:

- **[`<Stack>`]([[docsref:/components/stack]])** for a single row or column of items, like a button toolbar or the fields of a form.
- **[`<Flex>`]([[docsref:/components/flex]])** for items as wide as their content, and for wrapping, justification, and alignment along one axis.

Reach for `<Grid>` when items share column tracks: page layouts, card grids, and forms whose fields line up across rows.

## How it works

The grid system combines breakpoints, containers, a grid, and its items into one layout model:

- **The grid follows [six breakpoints](https://chassis-ui.com/css/docs/layout/breakpoints).** Breakpoints are `min-width` media queries, so a value set for one applies to it and to every wider one: `responsive={{ sm: { span: 4 } }}` holds from `sm` up, until another key overrides it.

- **Containers center the page and pad its sides.** Use `<Container>` for a width per breakpoint, `<Container fluid>` for the full width, or `<Container fluidUntil="md">` for a mix. The padding of a container is the page margin, separate from the gutter of the grid.

- **A grid has twelve columns.** `<Grid>` divides its width into equal tracks. `columns` changes the count, for the whole grid or from a breakpoint up.

- **Items span tracks.** `<GridItem span={4}>` takes four of the twelve. An item with no `span` is one track wide, so an item that should fill the row takes `span="full"`.

- **The gutter follows the breakpoint.** With no `gap`, the space between items is the gutter of the current breakpoint, from 0.5rem on a phone to 3rem on the widest screens, in both directions. `gap` sets another, for the whole grid or from a breakpoint up.

## Equal columns

Columns of the same width need no span on each item: the grid counts them for you, or you give it
the count.

### As many as children

`<Grid fill>` gives every child a column of the same width, however many there are. Add `min` to
wrap the children once a column would get narrower than that.

<Example class="cxd-example-grid text-center">
  <EqualWidthExample client:load />
</Example>

### A count per breakpoint

`columns` sets how many equal columns a grid has, and `responsive` changes the count as the
viewport widens. Further children wrap to the next row. This is what `<Row cols>` did.

<Example class="cxd-example-grid text-center">
  <ColumnCountsExample client:load />
</Example>

## Spans

On the twelve default columns, `span` gives each item its own width.

### All breakpoints

A `span` outside `responsive` holds from the narrowest viewport to the widest.

<Example class="cxd-example-grid text-center">
  <AllBreakpointsExample client:load />
</Example>

### Stacked to horizontal

Give the items `span="full"` and a narrower span from a breakpoint up, and they start out stacked
and sit side by side from that breakpoint. A column count does the same for equal columns:
`columns={1}` below the breakpoint, more from it.

</Example>

### Mix and match

## Start lines

`start` puts an item at a column line and leaves the tracks before it empty, which is how you
indent or center an item. Unlike the `offset` of `<Col>`, a start line counts from the edge of the
grid, not from the item before. Don't center a grid item with an auto margin: it shrinks the item to
its content.

<Example class="cxd-example-grid text-center">
  <StartExample client:load />
</Example>

## Gaps

The gap is the space between items, set on the grid and not on the items. There are no negative
margins, so a grid never overflows its container the way a row with wide gutters did.

### Both axes

`gap` takes a token of the spacing scale and applies it between columns and between rows.
`responsive` changes it from a breakpoint up.

<Example class="cxd-example-grid text-center">
  <GapExample client:load />
</Example>

### One axis

The `.column-gap-{token}` and `.row-gap-{token}` utilities set one axis each, in place of the
`gutterX` and `gutterY` of `<Row>`. `row-gap-zero` suits items that carry a bottom margin of their
own.

<Example class="cxd-example-grid text-center">
  <AxisGapExample client:load />
</Example>

### No gap

`gap="zero"` removes the space on both axes, for items that should touch.

</Example>

## Content-width columns

A grid sizes its tracks from the container, not from the content. For items as wide as their
content beside items that take the rest of the row, use a [`<Flex>`]([[docsref:/components/flex]])
with a `gap`, and `.flex-fill` on the items that grow.

<Example class="cxd-example-flex text-center">
  <VariableWidthExample client:load />
</Example>

## Nested grids

A `<Grid>` inside an item is a grid of its own, with twelve tracks across the width of the item.
The default gutter follows the viewport, not the width of the grid, so in a nested grid — or one in
a sidebar or a card — it is too wide for twelve tracks. Give such a grid a `gap` and a column count
that fits.

<Example class="cxd-example-grid text-center">
  <NestedExample client:load />
</Example>

To align nested items with the outer columns instead, make the item a
[subgrid]([[docsref:/components/grid#subgrid]]).
