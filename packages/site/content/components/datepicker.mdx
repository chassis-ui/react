## Overview

`DatePicker` combines an individually-editable segmented date field (day/month/year, each a separate keyboard-navigable unit) with a calendar popover — type a date directly or pick one from the grid. Both stay in sync with a single selected value. The popover renders [`Calendar`]([[docsref:/components/calendar]]), which is also available on its own wherever an inline, non-popover calendar is needed.

## As a form field

Pass `label`/`help` to wrap the date picker in a `.form-field` with an associated `FormLabel` and `FormHelp`. Pass `name` to have `DatePicker` create and manage a hidden `<input>` for native form submission — its value stays in sync with the selection, formatted as an ISO 8601 date string (`2026-07-24`), with a time `2026-07-24T09:30:00` (see [Time](#time)).

## Min & max dates

Restrict the selectable range with `minValue`/`maxValue`. Dates outside the range are shown but disabled in the calendar grid. A value typed outside the range marks the field invalid, as `invalid` does, and shows `invalidFeedback` if there is one.

## Time

Pass `granularity` as `'hour'`, `'minute'` or `'second'` to add a time to the field. Its segments follow the date's in the locale's order and hour cycle (`hourCycle` sets 12 or 24 hours), and the value becomes a `CalendarDateTime`. A value that carries a time shows it without `granularity`; with a time granularity, a value or `placeholderValue` must carry one (a `CalendarDate` there throws).

The calendar picks the day and the field's segments edit the time. Picking a day keeps the time already set, so the day changes without retyping it. In an empty field it takes the time of `defaultValue`, else of `placeholderValue`, else midnight. `minValue`/`maxValue` may carry a time: the calendar compares days only, so their own days stay selectable, and a time outside the range marks the field invalid.

<Example>
  <TimeExample client:load />
</Example>

A `ZonedDateTime` as `value`, `defaultValue` or `placeholderValue` adds its time zone to the field (`hideTimeZone` leaves it out), and `onChange` receives `ZonedDateTime`s. A day picked after the field is cleared is built from `defaultValue` or `placeholderValue` as above, so a controlled zoned `value` needs a zoned `placeholderValue` too, or the next value is a `CalendarDateTime` with no zone. The hidden input holds the zone too, `2026-11-05T09:30:00+09:00[Asia/Tokyo]`, which `parseZonedDateTime` reads back. The calendar shows that zone's days, and marks today by that zone's date.

## Locale & calendar system

`DatePicker` reads locale from React Aria's `I18nProvider` (or the browser's locale if none is set). Segment order, weekday names, and the calendar system itself all follow the active locale — this example uses `ar-SA`, which renders right-to-left and uses the Umm al-Qura calendar instead of Gregorian. See [Internationalization]([[docsref:/getting-started/internationalization]]) for setting a locale and its relationship to RTL layout.

## Unavailable dates

Pass `isDateUnavailable` to mark specific dates as unselectable without excluding them from the grid — useful for booked dates or holidays. Unavailable dates remain focusable (so screen reader users can discover why they can't be picked) but can't be selected. This applies to both the calendar popover and typing a date directly into the field.

For data-driven cases, pass `unavailableDates` instead — a plain array of ISO 8601 (`YYYY-MM-DD`) strings — as a convenience alternative. It composes with `isDateUnavailable` when both are given.

## Weekend styling

Saturday/Sunday (or whichever days the active locale considers the weekend) are shown muted in the calendar popover automatically — inherited from [`Calendar`]([[docsref:/components/calendar]]), no prop required.

## First day of week

The calendar popover's week starts on Monday by default, regardless of the active locale. Pass `firstDayOfWeek` to override it, same as [`Calendar`]([[docsref:/components/calendar]]).

## Multiple dates

Pass `selectionMode="multiple"` to select any number of independent dates instead of one. A segmented day/month/year field can't represent more than one date, so multiple selection replaces it with a read-only, comma-separated list of the selected dates — the calendar popover still works the same way, just toggling dates on and off instead of replacing a single value. `value`/`defaultValue`/`onChange` switch from a single date to an array of dates, and a `name`'d hidden input is created per selected date instead of just one.

## Controlling the popover

The popover manages its own open state by default. Pass `visible` (with `onVisibleChange`) to drive it from outside instead — e.g. to open the calendar from a button elsewhere on the page. `defaultVisible` sets the initial open state for the uncontrolled case, without taking over control. The earlier names `isOpen`, `onOpenChange` and `defaultOpen` still work and are deprecated.

## Styling

Unlike most Chassis React components, `DatePicker`'s calendar grid isn't styled by `@chassis-ui/css` — chassis-css's own datepicker styling is built entirely around [Vanilla Calendar Pro](https://vanilla-calendar.pro/)'s specific DOM output, which React Aria's calendar hooks don't produce. The grid itself is styled by [`Calendar`]([[docsref:/components/calendar]])'s own scoped CSS (built on `@chassis-ui/tokens`' public design tokens, so it still matches the current theme and light/dark mode), and `DatePicker` adds its own for the field's segments and the popover shell, all in `@chassis-ui/react/style.css`, which an app imports once (see [Theming]([[docsref:/getting-started/theming]])). The field and toggle button, in turn, reuse chassis-css's existing `.form-input`/`.input-adorn`/`.ghost-input` classes as-is.

## Scope

The strong-fit case for React Aria's date picker hooks is a single editable date field. A few things are deliberately out of scope for this pass:

- **Date ranges** — for a start/end range, see [`DateRangePicker`]([[docsref:/components/date-range-picker]]), built on the separate `useDateRangePickerState`/`useDateRangePicker` hook pair.
- **A time picker in the popover** — the time is edited in the field's segments, and the popover picks the day only. For a time with no date, use [`TimeField`]([[docsref:/components/time-field]]).
- **A time with multiple dates** — `granularity` applies to single selection; `selectionMode="multiple"` lists dates only.
