## Examples

`<Chip>` renders a `<span>` by default, styled with the `color` prop for one of Chassis's context
colors. It's a compact, composable building block for tags, filters, and selections — combine it
with `Icon`, `Avatar`, or `CloseButton` as plain children.

<Example>
  <BasicExample client:load />
</Example>

## Colors

Set `color` to one of Chassis's context colors.

<Example class="d-flex flex-wrap gap-small">
  <ColorExample client:load />
</Example>

<Callout type="info">
  Color alone doesn't convey meaning to assistive technology. Pair a context color with visible
  text describing the chip's purpose.
</Callout>

## Sizes

Set `size` to `"small"` or `"large"` to adjust a chip's padding and font size; the default renders

## Pressed state

Set `pressed` to mark a toggle-style chip as active — e.g. a filter pill that stays highlighted
while selected. It applies the `.active` class and sets `aria-pressed`, so assistive technology
announces the toggle state. `Chip` doesn't toggle itself; flip `pressed` from an `onClick`
handler.

<Example>
  <PressedExample client:load />
</Example>

## Root element

Set `component` to render `<Chip>` as a different element — `"div"` for a non-interactive block,
`"button"` for a toggle control, or any custom component. `href` implies `component="a"`
automatically.

<Example class="d-flex flex-wrap gap-small">
  <ComponentExample client:load />
</Example>

<Callout type="info">
  A chip rendered as `<a>` for something other than navigation — a toggle filter, for example —
  needs an explicit `role="button"`; Chassis doesn't add it automatically, since not every
  `component="a"` usage is a non-navigation action.
</Callout>

## Disabled state

Set `disabled` to make a chip non-interactive. A `<button>` chip uses the real `disabled`
attribute, which blocks keyboard and pointer interaction on its own.

<Example>
  <DisabledExample client:load />
</Example>

`<span>`, `<div>`, and `<a>` have no `disabled` attribute, so a disabled non-button chip gets the
`.disabled` class instead, which sets `pointer-events: none`. A disabled `<a>` chip additionally
gets `aria-disabled="true"` and `tabindex="-1"`, and blocks its own click handler and navigation.

<Example>
  <DisabledLinkExample client:load />
</Example>

## Scope

**No automatic `role="button"` on non-navigation links.** Rendering `<Chip>` with `component="a"`
for a toggle action rather than navigation (see [Root element](#root-element)) still needs an
explicit `role="button"` — Chassis can't distinguish the two cases from `href` alone.

**No built-in list management.** Unlike [`ChipInput`]([[docsref:/components/chip-input]]), `Chip`
renders a single chip with no concept of a value collection — creation, removal, and keyboard
navigation across a set of chips are the consumer's responsibility (or use `ChipInput`, which
composes `Chip` internally for exactly that use case).
