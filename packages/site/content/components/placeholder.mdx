## Overview

`<Placeholder>` renders an inline `<svg>` sized to `width`/`height`, filled with a context color
and a `{width}x{height}` label — useful for mocking up layouts before real images exist. Pass
`src` and it renders a real `<img>` instead (or any component passed via `component`), so the same
component can point at a project's own default image, a `placehold.co` URL, or any other source
once one is available — no need to swap components as content comes online.

- `width` and `height` size the graphic and (unless overridden) generate its default label text.
- `color` sets the generated graphic's background/foreground to one of the context colors. Has no
  effect when `src` is set.
- `text` and `title` override or hide (`false`) the generated graphic's label and accessible
  title. Have no effect when `src` is set.
- `src` switches to rendering a real image, forwarding any other native `img` props
  (`alt`, `loading`, `srcSet`, …) alongside it. Only applies when `src` is set: `fluid` (responsive,
  `image fluid`), `thumbnail` (`image thumbnail`), `rounded`, and `align` (`start`/`center`/`end`).
- `component` swaps the `<img>` rendered in `src` mode for any other element or component — see
  [Using a custom image component](#using-a-custom-image-component).

### Using a custom image component

`<Placeholder>` renders a plain `<img>` in `src` mode by default, but its `component` prop accepts
any element or component — including a framework's own `Image` (Next.js, Gatsby, Remix, etc.).
Whatever is passed is fully type-checked at the call site, so a component's own props (`fill`,
`priority`, `loader`, and so on) are available and validated alongside `src`/`alt`:

```tsx
import Image from 'next/image'

<Placeholder component={Image} src="/hero.jpg" alt="" fill priority />
```
