## Overview

`OtpInput` renders `length` single-character boxes (`6` by default) with automatic focus advancement after each digit, backspace navigation back to the previous box, arrow-key navigation, and full-code paste distribution. The first box gets `autocomplete="one-time-code"` for SMS/email code autofill on supported browsers.

## Grouped with a separator

Pass `groupSizes` (e.g. `[3, 3]`) to split the boxes into groups with a `–` separator between them — the total number of boxes becomes the sum of `groupSizes`, overriding `length`. Combine with `inputGroup` to connect each group separately.

## As a form field

Pass `label`/`help` to wrap the group in a `.form-field` with an associated `FormLabel` (linked via `aria-labelledby`, since there's no single input to target with `htmlFor`) and `FormHelp`. Pass `name` to have `OtpInput` create a hidden `<input type="hidden">` kept in sync with the code, for native form submission.

## Keyboard interaction

- <kbd>0</kbd>–<kbd>9</kbd> enters a digit and advances focus to the next box.
- <kbd>←</kbd>/<kbd>→</kbd> move focus between boxes.
- <kbd>Backspace</kbd> on an empty box clears and focuses the previous box; on a filled box, clears it in place.
- <kbd>Delete</kbd> clears the focused box and shifts every following digit one box left.
- Pasting a full code anywhere distributes it across all boxes from the first one.

## Accessibility

Each box has no visible label, so it carries its own `aria-label` (`"Digit 1"`, `"Digit 2"`, …) generated automatically — screen readers announce each box's position. Label the group as a whole with `aria-label` or `aria-labelledby` on `OtpInput` itself, and associate help text with `aria-describedby`.

## Scope

Built on React Aria's `useTextField`/`useFocusRing` per box — there's no dedicated "OTP input" hook, so auto-advance, backspace/delete navigation, and paste-splitting are hand-written to match chassis-css's vanilla `otp-input.js` behavior, same framing as the plan's own description of this as the closest-to-hand-rolled of the newer form widgets.

Unlike the vanilla component, `OtpInput` doesn't expose imperative `focus()`/`clear()` methods or a `complete`/`input` DOM event pair — use the declarative `value`/`defaultValue`/`onChange`/`onComplete` props instead.
