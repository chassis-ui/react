## Basic usage

Place one add-on or button on either side of an input, or on both sides at once. Place
`<FormLabel>`s outside the input group, rather than inside it.

<Example class="vstack gap-medium">
  <BasicExample client:load />
</Example>

## Wrapping

An input group wraps by default via `flex-wrap: wrap`, accommodating custom form field validation
within the group. Disable this with the `.flex-nowrap` class.

<Example>
  <WrappingExample client:load />
</Example>

## Sizing

Add the relative form sizing classes to `<InputGroup>` itself, and its contents resize
automatically — no need to repeat the form control size classes on each element.

<Callout type="warning">
  Sizing on the individual input group elements isn't supported.
</Callout>

<Example>
  <SizingExample client:load />
</Example>

## Custom forms

Input groups support custom selects and custom file inputs. Browser default versions of these
controls aren't supported.

### Custom select

A `<Select>` composes into an input group the same way a `<TextInput>` does, with an addon on
either side.

<Example>
  <CustomSelectExample client:load />
</Example>

### Custom file input

A `<FileInput>` composes into an input group the same way, pairing with a label-style addon or a
button.

<Example>
  <CustomFileInputExample client:load />
</Example>
