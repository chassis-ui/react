## Examples

Pass `label` to `FloatingInput` and wrap a `TextInput`, `Select`, or `Textarea` to enable floating
labels with textual form fields. `FloatingInput` renders the floating `<label>` itself and ties it
to the control inside, so pass neither `label` nor an `id` to the wrapped control. A `placeholder`
is required on each `<TextInput>`, since this CSS-only technique relies on the
`:placeholder-shown` pseudo-class.

<Example>
  <TextInputsExample client:load />
</Example>

The label floats automatically when the wrapped control already has a `value`.

<Example>
  <ExistingValueExample client:load />
</Example>

## Help and feedback

Passing `help`, `invalid`/`invalidFeedback`, or `valid`/`validFeedback` wraps the floating input
in a `.form-field` and renders the corresponding text below it, same as the other form components.
The control inside is described by the text that shows. Set `invalid`/`valid` on the control as
well: its state is what shows the feedback and draws its border.

</Example>

## Selects

Floating labels also work with `<Select>`, though a select's label always renders in its floated
state rather than overlapping the value. **Selects with `size` or `multiple` set aren't supported.**

## Other controls

`FloatingInput` generates the ids of its label, help and feedback, and a `TextInput`, `Select` or
`Textarea` inside takes them by itself. Any other control, such as a native `<input>`, takes them
by hand: choose the ids, pass them through the `ids` prop, and repeat them on the control, as for
a [`<FormField>`]([[docsref:/components/form-field#manual-id-wiring]]). The control needs the
`.form-input` class and has to be a direct child, which is what the label floats over.

<Example>
  <NativeControlExample client:load />
</Example>

`ids` also replaces a generated id with one of your own, for a test or a link to the field:
`ids={{ input: 'email' }}` gives the wrapped `TextInput` the id `email`. In development,
`FloatingInput` warns when no element has the id its label points at.
