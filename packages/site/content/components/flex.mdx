`<Flex>` turns an element into a flexbox container (`.d-flex`, or `.d-inline-flex` when `inline` is set) and exposes the underlying flex properties as props: `direction`, `wrap`, `justify`, `align`, `alignContent`, `gap`/`rowGap`/`columnGap`, plus a `responsive` prop for overriding any of these at specific breakpoints.

Reach for [`<Stack>`]([[docsref:/components/stack]]) first for simple one-dimensional arrangements — it wraps `.hstack`/`.vstack` with alignment defaults baked in. Reach for `<Flex>` instead once more control is needed than Stack's defaults give: wrapping, main-axis justification, cross-axis alignment other than Stack's fixed default, or no default flex/align behavior at all (a bare `.d-flex` with nothing else set).

## Basic usage

With no props, `<Flex>` is a plain flexbox row using the browser's defaults (`flex-direction: row`, no wrap, items stretched to the container's cross-axis size):

## Wrap

`wrap` sets `flex-wrap`, letting items move onto new lines instead of overflowing or shrinking to fit. Once a container wraps, `align` still governs how each item sits within its own line; `alignContent` (below) governs how the lines themselves are spaced.

## Align content

`alignContent` sets `align-content`, distributing wrapped lines along the cross axis. It has no effect on single-line (non-wrapping) containers, so it only does something combined with `wrap`:

## Row and column gaps

`gap` sets spacing on both axes at once. `rowGap`/`columnGap` control each axis independently, and take precedence over `gap` on their own axis — useful once a wrapped container needs different spacing between lines than between items on the same line.

## Responsive

The `responsive` prop overrides any of `direction`/`wrap`/`justify`/`align`/`alignContent`/`gap`/`rowGap`/`columnGap` at one or more breakpoints, keyed by the full breakpoint names (`small`/`medium`/`large`/`xlarge`/`2xlarge`). Unlike [`<Stack>`'s `responsive` prop]([[docsref:/components/stack#responsive-direction]]), which relies on container queries, `Flex`'s responsive classes are plain viewport `min-width` media queries — no `.contains-inline` ancestor needed. Below the `medium` breakpoint the container stacks its children in a column; at `medium` and above it switches to a row with items spaced apart:

<Example class="cxd-example-flex">
  <ResponsiveExample client:load />
</Example>

## Item-level utilities

`<Flex>` covers container-level properties only. Per-item concerns — `align-self`, `order`, `flex-grow`/`flex-shrink`, `flex-fill`, or an auto-margin spacer like `.ms-auto` — apply directly via `className` on a child, the same as with plain chassis-css markup.
