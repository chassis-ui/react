## Overview

Carousel is a content slider built on a real horizontally-scrolling `CarouselInner` track using CSS scroll-snap, rather than transform-based slide positioning. The browser handles touch, trackpad, and mouse-drag scrolling natively; Carousel layers on keyboard navigation, autoplay, and end-of-track behavior on top, tracking which slide is active with an `IntersectionObserver` rather than a fixed index the caller has to keep in sync by hand.

The family composes from a root and five optional parts: `CarouselInner` wraps the `CarouselItem` slides that scroll; `CarouselControlPrev`/`CarouselControlNext` step through them; `CarouselIndicators` renders one button per slide automatically, sized to however many `CarouselItem`s are actually present; `CarouselPlayPause` toggles autoplay; and `CarouselOverlay` overlays any of the above on top of the slides instead of stacking them in the flow. Every part reads from Carousel's own state through context, so placement is free-form — controls and indicators can sit above, below, or overlaid on the track in any combination.

## Autoplay

Set `autoplay` to cycle a carousel automatically on mount. Autoplay pauses on `mouseenter` by default (the `pause` prop) and stops advancing once the page or the carousel itself isn't visible, per the [Page Visibility API](https://www.w3.org/TR/page-visibility/). The first control click, arrow-key press, or track drag/tap turns autoplay off for good, so content doesn't keep moving out from under someone who's just started interacting with it — part of complying with [WCAG 2.2 Success Criterion 2.2.2 Pause, Stop, Hide](https://www.w3.org/TR/WCAG/#pause-stop-hide).

<Callout type="warning">
  Autoplaying carousels need an explicit pause/stop control to comply with [WCAG 2.2 Success
  Criterion 2.2.2 Pause, Stop, Hide](https://www.w3.org/TR/WCAG/#pause-stop-hide). Add a
  `CarouselPlayPause` (shown below) so a viewer can toggle autoplay on and off — it updates its own
  icon and accessible name to reflect the current state, from the `pauseLabel`/`playLabel` props.
</Callout>

While playing, the active indicator fills like a progress bar over the current slide's [interval](#timing-control) as a visual countdown; the fill pauses with autoplay and is skipped entirely under reduced motion.

## End behavior

The `ends` prop controls what happens at the first and last slide: `loop` (the default), `wrap`, or `stop`.

### Loop (default)

With `ends="loop"` the carousel scrolls seamlessly past the ends: stepping next from the last slide (or previous from the first) continues in the same direction into the destination slide instead of jumping back, for an endless conveyor effect. Seamless looping applies to single-slide carousels driven by the controls, keyboard, or autoplay; multi-item, peek, centered, and variable-width layouts — as well as reduced motion — fall back to the `wrap` jump.

<Example>
  <LoopExample client:load />
</Example>

### Wrap

With `ends="wrap"` the carousel jumps from the last slide back to the first, and vice versa.

### Stop

With `ends="stop"` the carousel hard-stops at the first and last slide: `CarouselControlPrev` disables on the first slide and `CarouselControlNext` on the last, via the native `disabled` attribute. When a focused control becomes disabled, focus shifts to the opposite control so it isn't lost.

## Controlled usage

A controlled `activeIndex` needs an `onSlide` or `onSlid` handler feeding the new index back — every click, swipe, or autoplay advance calls one of them with the destination index, and that's the only path a controlled carousel has for updating its own `activeIndex`.

<Callout type="warning">
  Omitting both `onSlide` and `onSlid` on a controlled `activeIndex` leaves the carousel visually
  frozen after the first navigation attempt: internal state still advances, but the controlled
  prop overrides it back on every render. `Carousel` warns about this pairing in development.
</Callout>

## Accessibility

Carousel accessibility centers on keyboard control, focus preservation at the ends, and ARIA state that mirrors the current slide.

With `keyboard` enabled (the default), Left Arrow and Right Arrow move to the previous and next slide while focus is inside the carousel; either key turns autoplay off for good, the same as a control click. Arrow keys inside a nested `<input>`, `<textarea>`, `<select>`, or `[contenteditable]` element are left alone so native form navigation keeps working.

`CarouselIndicators` sets `aria-current="true"` on the active indicator and gives each one its own `aria-label` identifying the slide it jumps to (`Slide 1`, overridable through its `label` prop). `CarouselControlPrev`/`CarouselControlNext` carry a `visually-hidden` label by default (`Previous slide`/`Next slide`, overridable through their own `label` prop) so the icon-only buttons still have an accessible name.

## Scope

- **No CarouselCaption.** An earlier version shipped a caption sub-component tied to a `.carousel-caption` class that the underlying CSS framework no longer provides. Compose caption content directly inside a `CarouselItem` instead — see [Custom content](#custom-content).
