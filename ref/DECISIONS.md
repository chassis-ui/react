# Decisions

Why this repository's build, tests and CI are the way they are. The agent guides (`AGENTS.md`,
`packages/react/AGENTS.md`) and the comments in `.github/workflows/ci.yml` state the rule and cite
the ID; the history behind it lives here.

IDs are this repository's own, written "RD". Ecosystem decisions in chassis-website's
`ref/ROADMAP.md` are "D" numbers and aren't repeated here.

Add a row when a rule changes because something went wrong or a choice was made between options.
Change the outcome of an existing row rather than adding one that contradicts it.

The date is the first commit that carries the decision. History up to 2026-09-22 was squashed
(`d02bbd5d` on 2026-08-31, `02594b4a` on 2026-09-15), so a date in that range can be later than
the decision itself.

| ID   | Decision                                      | Outcome                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                | Date                                       |
| ---- | --------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------ |
| RD1  | Bundler and output format                     | tsdown (Rolldown) replaced Rollup. The output is ESM only: no consumer needs two formats. tsdown bundles the declarations itself, so there is no separate `tsc` declaration pass.                                                                                                                                                                                                                                                                                                                                                                                                                                      | 2026-08-31                                 |
| RD2  | No `engines` field in `packages/react`        | The package carried `engines.node: '>=24'`. It warned on install for consumers on older Node, failed `npm install` under engine-strict, and made tsdown emit for `node24.0.0`, because tsdown derives its target from that field. `tsdown.config.ts` now sets `target: 'es2022'`, the floor of `browserslist`.                                                                                                                                                                                                                                                                                                         | 2026-09-15                                 |
| RD3  | `sideEffects` names `dist/` paths             | It named `./src/utils/suppressFocusRingGlobally.ts`, which no consumer resolves, so the whole published bundle counted as side-effect-free while it installed a global listener. It now names the entries, the focus-ring chunk and `style.css`. Rolldown applies the field to `src/` as well, where it matches nothing, so `tsdown.config.ts` marks that module side-effectful for the build.                                                                                                                                                                                                                         | 2026-09-22                                 |
| RD4  | `'use client'` comes from each entry's source | Rolldown keeps the directive of an entry module. A `tsdown.config.ts` `output.banner` also added one, which put two in the output. The banner was removed; `pnpm check:rsc` asserts exactly one per entry and none in shared chunks.                                                                                                                                                                                                                                                                                                                                                                                   | 2026-09-15                                 |
| RD5  | Bundle-size gate                              | Under Rollup, react-aria and react-stately were once bundled into `dist/`: 344 kB gzip, 65 kB once fixed. tsdown externalizes `dependencies` and `peerDependencies` by default, and `pnpm react:check:bundle` stays as the guard. Baselines when minification was turned on: 27.69 kB JS and 1.18 kB CSS (36.11 kB and 4.75 kB before). Since the build split into one entry per component folder, the ceilings are per file.                                                                                                                                                                                          | 2026-08-31, per file 2026-09-22            |
| RD6  | Type-check gate in CI                         | Before `pnpm react:check:types` ran in CI, four type errors reached `main`. One was a `usePagination` return type that called its refs non-null when `useRef<T>(null)` makes them nullable, and it shipped in the published types.                                                                                                                                                                                                                                                                                                                                                                                     | 2026-09-15                                 |
| RD7  | `lint:eslint` runs each package's own script  | The root script globbed `packages/**/src/**`, which left `stories/`, `test/`, `scripts/` and `.storybook/` unlinted in CI. Four broken Storybook interaction tests reached `main` through that gap.                                                                                                                                                                                                                                                                                                                                                                                                                    | 2026-09-15                                 |
| RD8  | Generated API JSON is gated                   | The files under `packages/site/content/api/` embedded the generating machine's checkout path, all 148 of them, so no two machines produced the same output, and nothing noticed when a props change skipped `react:generate`: the docs showed a stale prop table. `build/generate-api.ts` now writes repo-relative paths, which made the `pnpm react:check:api-docs` gate possible.                                                                                                                                                                                                                                    | 2026-09-15                                 |
| RD9  | Full site build in CI                         | The static build couldn't be a gate while a workspace override linked in the sibling `../chassis-css` checkout, whose in-progress Sass failed it. The override was dev-only and was removed; the site builds against the published `@chassis-ui/css`, and the `site-build` job gates it.                                                                                                                                                                                                                                                                                                                               | 2026-09-15                                 |
| RD10 | HTML validator exceptions                     | Only markup that is correct gets an exception. The ones that covered library defects (finding F10 of the second audit pass) were deleted with the fixes.                                                                                                                                                                                                                                                                                                                                                                                                                                                               | 2026-09-30                                 |
| RD11 | Coverage provider and thresholds              | istanbul, not v8, to keep the branch and statement counting the thresholds were tuned against. The thresholds were 91/79/93/93 (statements, branches, functions, lines), 6 to 14 points below measured coverage, so branch coverage could fall by a seventh before anything failed. Re-baselined to 96/91/97/97 against the jsdom project alone (measured 97.20/92.82/98.26/98.78), so the gate means the same whether or not the browser project ran.                                                                                                                                                                 | istanbul 2026-07-28, thresholds 2026-09-15 |
| RD12 | No markup snapshots in component specs        | 105 of 128 spec files had a raw `toMatchSnapshot()` of `container`, and 11 more had a second one. An audit found every one duplicated assertions a few lines away in the same file. None covered what explicit assertions can't: the overlay families' snapshots pinned inline `position` styles that jsdom can't lay out, and those families have visual regression. All were removed and replaced by the assertions they shadowed; `eslint.config.js` bans the pattern under `test/components/**`.                                                                                                                   | 2026-08-31                                 |
| RD13 | Vitest replaced Jest                          | Jest ran through ts-jest. Vitest's fake timers don't fake `requestAnimationFrame` by default, as Jest's did, so the config adds it: react-aria schedules hover and press updates with it.                                                                                                                                                                                                                                                                                                                                                                                                                              | 2026-08-31                                 |
| RD14 | Linux baselines come from one script          | Running Playwright's image by hand has three traps. `pnpm install` over a bind mount rebuilds the native dependencies (esbuild, sharp, `@parcel/watcher`) as Linux binaries in the host's `node_modules`, so `scripts/update-linux-snapshots.sh` copies the repository in and out. The image is multi-arch and runs arm64 on Apple Silicon unless forced to `linux/amd64`, CI's architecture. macOS `tar` adds `._*` files that Playwright loads as specs. The script also reruns each regenerated spec twice: `toast-notification.visual.spec.ts` once saved a mid-transition screenshot that failed on the next run. | 2026-08-31                                 |
| RD15 | Visual regression in Playwright's image       | The job began with the calendar/datepicker family, after the enterprise migration's Phase 2 changed its CSS output, which DOM tests can't see. It runs in the official Playwright image so the pixels match the Linux baselines; the image tag has to match the `@playwright/test` version.                                                                                                                                                                                                                                                                                                                            | 2026-08-31                                 |
| RD16 | Next.js smoke test loads its routes           | The smoke app builds against the workspace source, so it checks ESM-only resolution (RD1) through a real consumer's bundler. A build alone passed while `List` rendered `<ul><a>` and `Tabs` rendered no tabs, so the routes now load in a browser under `next start` and `next dev`.                                                                                                                                                                                                                                                                                                                                  | 2026-08-31, browser 2026-09-30             |
| RD17 | Only the production audit blocks              | `pnpm check:pnpm` (`pnpm audit --prod --audit-level moderate`) blocks: a vulnerable runtime dependency ships to every consumer. The full audit doesn't: tooling advisories would keep the gate red. `pnpm audit` has no `--filter`, so the blocking step covers the site's production dependencies too. Two `image-size` advisories reached it that way and were ignored until a patched release was out (#41). `brace-expansion` 1.x, through the site's `html-validate`, is overridden to 1.1.21. Steps of Build until 2026-10-02; now the Audit job: the release reads it, the ruleset doesn't require it.          | 2026-08-31, own job 2026-10-02             |
| RD18 | One workflow shape with the sibling repos     | D24 of chassis-website's `ref/ROADMAP.md`. Every job and step is named: `site-build` and `smoke-test-nextjs` are Site and Smoke Test. Dependency Review is a job of `ci.yml`. The Changeset job is new: a change could reach `main` without a changeset. The release runs `npm publish --tag <dist-tag>`, not `changeset publish`, which sent every version to `latest`, and reads its notes with `build/release-notes.js`. Tags are `v<version>` after 0.2.0. The ruleset requires Lint, Type Check, Test, Build, Site, Visual Regression and Smoke Test; the release reads those and Audit.                          | 2026-10-02                                 |
| RD19 | Breakpoints live on each prop                 | Eight layout components took one `responsive` prop, an object keyed by breakpoint that held the props of that breakpoint. No other React library has that map: Chakra, Mantine, Radix Themes, Primer and MUI's Grid v2 key each prop by breakpoint. Each prop now takes `Responsive<T>`: the value, or `{ base, sm … 2xl }`, with the `@` keys on `Grid` and `GridItem`. Props named after a breakpoint (`md={6}`) fit one property per component. The class order is unchanged. Removed in 0.4.0 with `Row` and `Col`, without the deprecation release of `VERSIONING.md`.                                            | 2026-10-07                                 |
| RD20 | Utility classes are whole names in the source | In the Tailwind entry of chassis-css a utility has a rule only where Tailwind's scanner finds its whole name, which cannot read `` `bg-${color}` ``: the class had no rule and nothing warned (#54). A prop with a small set of values maps to whole class names from a table, read out of `dist` once a project adds a `@source` for the package. The layout props can render 1,503 classes: they stay built at runtime, and a Tailwind build loads the safelist of chassis-css (css#24). Declined: custom properties in `style`; tables for the layout props. Guard: `test/utils/tailwindClassNames.spec.tsx`.       | 2026-10-09                                 |
