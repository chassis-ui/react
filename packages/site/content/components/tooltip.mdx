## Overview

`<Tooltip>` wraps a single trigger element and shows floating `content` positioned relative to it
on hover. It also shows on focus regardless of the `trigger` setting, so keyboard and
screen-reader users reach the same content a pointer user gets on hover — set `trigger="focus"` to
disable the hover trigger entirely, for a trigger whose hover state already means something else.

## Placement

Set `placement` to one of the four cardinal directions, each with `-start`/`-end` variants for
finer alignment along the trigger's edge. Chassis flips the requested direction automatically to
keep the tooltip in view when there isn't enough room for it. Directions mirror automatically when
Chassis renders in RTL.

## Controlling the tooltip

A tooltip shows and hides itself. Pass `visible` with `onVisibleChange` to hold the state
yourself: hover, focus and the Escape key are then reported to `onVisibleChange` with the state
they ask for, and the tooltip changes only when `visible` does.

```tsx
const [visible, setVisible] = useState(false)

<Tooltip content="Copy link" visible={visible && !menuOpen} onVisibleChange={setVisible}>
  <Button onClick={copy}>Copy</Button>
</Tooltip>
```

`visible` alone holds the tooltip shown or hidden whatever the pointer does. In development the
first request it drops is logged, since a missing `onVisibleChange` is more often a mistake than a
choice. `defaultVisible` shows the tooltip on first render and leaves it uncontrolled.

## The panel

Every other attribute goes to the panel, the `.tooltip` element: `className`, `style`, `id`,
`data-*` attributes. A `ref` on `<Tooltip>` points to the panel too, and is `null` while the
tooltip is hidden. The trigger keeps its own props and ref.
