## Overview

`<Progress>` renders both the wrapper and the inner bar from a single `value` prop, using its own markup instead of [the HTML5 `<progress>` element](https://developer.mozilla.org/en-US/docs/Web/HTML/Element/progress) for full control over color, stripes, animation, and text labels.

## Indeterminate

Set `indeterminate` when work is under way and how much of it is done isn't known: a page navigation, an upload before its size is known, a request with no progress events. The bar sweeps across the track, and the `aria-valuenow`, `aria-valuemin` and `aria-valuemax` attributes are left out, so a screen reader announces a progress bar and no percentage. `value` and `inlineValue` are ignored, and `showValue` keeps its place in the caption row empty, so nothing moves when a value arrives.

Add `striped` to fill the track with stripes instead of the sweep, and `animated` to move them. Text inside the bar belongs with `striped`: the sweep stretches the bar it is drawn with.

<Example class="vstack gap-md">
  <IndeterminateExample client:load />
</Example>

The sweep animates `transform` only, so it keeps running while the page is busy. Under `prefers-reduced-motion: reduce` it is replaced by still stripes. Set the `--cx-progress-indeterminate-animation` custom property to run an animation of your own, for example a bar that grows towards the end of the track for a page navigation:

```tsx
<Progress aria-label="Loading page" className="navigation-progress" height={3} indeterminate />
```

```css
@keyframes navigation-progress {
  from {
    transform: translateX(-100%);
  }
  to {
    transform: translateX(-10%);
  }
}

.navigation-progress {
  --cx-progress-indeterminate-animation: 8s cubic-bezier(0.1, 0.8, 0.2, 1) forwards navigation-progress;
}
```

The indeterminate bar is styled by [`@chassis-ui/react/style.css`]([[docsref:/getting-started/introduction#component-specific-styles]]), not by `@chassis-ui/css`.

### ProgressBar

`<ProgressBar>` is the presentational inner element `<Progress>` renders automatically. It's exported for advanced, manual compositions (for example custom stacked layouts) — for typical use, `<Progress>` alone is enough. An `indeterminate` segment of a stacked layout needs `striped`: the sweep is clipped by the track, not by its segment.
