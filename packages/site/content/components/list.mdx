## Overview

`<List>` renders a structured container for related content, with consistent spacing, borders, and
typography through Chassis's design token system. Beyond plain items, it supports interactive
elements, custom content, and composition with other components.

## Basic usage

`<List>` and `<ListItem>` build an unordered list, establishing the spacing, borders, and
typography the rest of this doc builds on.

</Example>

## Active items

Add the `active` boolean prop to a `<ListItem>` to mark it as the current selection. An active
item gets an `aria-current="true"` attribute automatically.

<Example>
  <ActiveExample client:load />
</Example>

## Disabled items

Add the `disabled` boolean prop to a `<ListItem>` to render it disabled. A disabled item gets an
`aria-disabled="true"` attribute automatically.

<Callout type="info">
  The disabled state only changes the visual appearance. For interactive elements like links,
  additional JavaScript is needed to fully disable interaction behavior.
</Callout>

<Example>
  <DisabledExample client:load />
</Example>

## Links and buttons

Set `component="a"` or `component="button"` to create actionable list items with hover, disabled,
and active states. This applies the `.list-action` modifier class, separating interactive states
from standard read-only items. Use `component="a"` when the action navigates to a new location, and
`component="button"` when it triggers an in-page behavior — a native `<button>`'s `disabled`
attribute both visually styles the element and prevents interaction, while an `<a>` only gets the
visual `.disabled` styling and needs additional JavaScript to fully prevent interaction.

Because `<a>`/`<button>` elements aren't valid children of a `<ul>`/`<ol>`, `<List>` automatically
renders its root as a `<div>` instead whenever an item is interactive (an interactive data-driven
item, or a `<ListItem component="a">`/`<ListItem component="button">` child) — pass `component`
explicitly if you need to override that.

</Example>

## Layout variations

### Flush list

Add the `flush` boolean prop to remove outer borders and rounded corners, rendering list items
edge-to-edge in a parent container (e.g., a card).

<Example>
  <FlushExample client:load />
</Example>

### Plain layout

Add the `plain` boolean prop for a minimal list that removes outer borders, rounded corners, and
horizontal padding — a compact fit for content areas like search results or content feeds.

<Example>
  <PlainExample client:load />
</Example>

<Callout type="info">
  Both `flush` and `plain` remove outer borders and rounded corners. `plain` also removes
  horizontal padding, for a more compact appearance.
</Callout>

### Numbered lists

Add the `numbered` boolean prop to sequentially number list items via CSS counters rather than
browser defaults. Pair it with `component="ol"` for semantic correctness.

<Example>
  <NumberedExample client:load />
</Example>

### Horizontal layout

Add `layout="horizontal"` to switch a list from column to row layout across all breakpoints.
Adjacent items share a single border edge, and outer corners stay rounded while inner corners are
squared off.

Responsive variants use [container queries](https://chassis-ui.com/css/docs/layout/breakpoints) —
each `layout="{breakpoint}:horizontal"` value activates at or above the specified container width.
Wrap the list in a `.contains-inline` container to establish the container context.

<Callout type="warning">
  `layout="horizontal"` cannot be combined with `flush` — the flush variant removes the inline
  borders that separate items in the horizontal layout.
</Callout>

<Example>
  <HorizontalExample client:load />
</Example>

Apply the `.flex-fill` or `.flex-grow-1` utility classes to list items to stretch them across the
full list width — `.flex-fill` shares the available width equally, while `.flex-grow-1` grows from
each item's natural content width.

<Example>
  <HorizontalFillExample client:load />
</Example>

## Contextual classes

Use the `color` prop to style list items with a stateful background and color.

<Example>
  <ContextualExample client:load />
</Example>

The same `color` prop works on `<a>`/`<button>` list items, adding hover styles not present on
plain items, alongside `active` to mark a current selection among them.

<Example>
  <ContextualLinksExample client:load />
</Example>

<Callout type="info">
  Context color alone provides only a visual indication, which isn't conveyed to assistive
  technology users. Make sure information denoted by the color is either obvious from the content
  itself (e.g. the visible text), or included through alternative means, such as additional text
  hidden with the `.visually-hidden` class.
</Callout>

### Context styles

color the whole list container based on the design system's color palette.
