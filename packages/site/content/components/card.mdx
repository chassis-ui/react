## Overview

A `<Card>` is a flexible content container built with flexbox, composing options for images, headers, footers, and a wide variety of body content. A card has no top, left, or right margin by default — spacing utilities apply as needed — and no fixed width to start, so it fills the full width of its parent.

## Basic usage

A basic card mixes an image, a title, body text, and a button inside a fixed width.

<Example>
  <BasicExample client:load />
</Example>

For the common case — a single image, a title, some text, maybe a footer — `<Card>` accepts
`image`/`imageAlt`/`imageOrientation`, `title`, `subtitle`, `text`, and `footer` shorthand props
directly, instead of composing `CardImage`/`CardBody`/`CardTitle`/`CardText`/`CardFooter`
directly. `title`/`subtitle`/`text`/`children` render together inside a single `CardBody`, in that
order, so `children` still works for trailing content like a button. This example produces the
same markup as the one above:

<Example>
  <ShorthandExample client:load />
</Example>

Shorthand props only take effect once at least one of `image`/`title`/`subtitle`/`text`/`footer`
is set — otherwise `children` render exactly as passed, so full manual composition (`CardHeader`,
flush lists, image overlays, nav headers, horizontal layouts, …) keeps working unchanged. Mixing
shorthand props with a manually-composed `children` tree (e.g. a raw `CardHeader`) isn't
supported — pick one approach per card, falling back to composing `CardBody`/`CardTitle`/etc.
directly for anything the shorthand props don't cover.

`image` also accepts a full element instead of a `src` string — a `<CardImage>` composed by hand,
a [`<Placeholder>`]([[docsref:/components/placeholder]]), a loading
[`<Skeleton>`]([[docsref:/components/skeleton]]) — rendered as-is in the image slot, so the rest of
`title`/`subtitle`/`text`/`footer` don't have to give up their shorthand just because the image
needs something other than a plain URL. `imageAlt`/`imageOrientation` only apply to the `src` form;
set them directly on the passed element otherwise. See
[Loading states]([[docsref:/patterns/loading-states]]) for a worked example swapping the image for
a skeleton while data loads.

## Content types

`<Card>` supports a wide variety of content, including images, text, lists, and links.

### Body

`<CardBody>` is the main padded content region of a card.

<Example>
  <BodyExample client:load />
</Example>

### Titles, text, and links

`<CardTitle>` renders a card's title, and `<CardLink>` renders links positioned next to each
other. `<CardSubtitle>` renders a subtitle — when both `<CardTitle>` and `<CardSubtitle>` sit
inside the same `<CardBody>`, their spacing lines up automatically.

<Example>
  <TitleTextLinksExample client:load />
</Example>

### Images

`orientation="top"` places an image at the top of the card. `<CardText>` renders text content,
styled with regular HTML tags as needed.

<Example>
  <ImageExample client:load />
</Example>

`<CardImage>` renders an `<img>` by default, but its `component` prop accepts any element or
component — including a framework's own `Image` (Next.js, Gatsby, Remix, etc.). The passed
component is fully type-checked at the call site, so its own props (`fill`, `priority`, `loader`,
and so on) are available and validated alongside `src`/`alt`:

```tsx
import Image from 'next/image'

<CardImage component={Image} src="/hero.jpg" alt="" fill priority orientation="top" />
```

## Images

Beyond a plain image inside a card, images support two more placements: "image caps" at either
end of a card, or an overlay behind the card's content.

### Image caps

## Horizontal

Set `direction="row"` (or `responsive` for a breakpoint-gated switch) on `<Card>` to lay it out
side-by-side instead of stacked. Wrap the image and body in `<Col>` to control each side's width,
and pair `orientation="top"` with a `responsive` override on `<CardImage>` so the image's rounded
corners switch from the top edge to the start edge at the same breakpoint the card switches to a
row.

<Example>
  <HorizontalExample client:load />
</Example>

To place the image inside a padded body region instead of flush against the card edge, apply
`direction`/`responsive` to `<CardBody>` itself and nest a second `<CardBody className="p-0">` for
the text side so it doesn't get double padding.

<Example>
  <HorizontalBodyExample client:load />
</Example>

## Card styles

A card supports several options for customizing its backgrounds, borders, and context.

### Context colors

Set `color` to one of the Chassis context colors, and `variant` to `solid`, `smooth`, or `outline`
to control the intensity — omit `variant` for the default (a tinted border and heading, matching
the `basic` chassis-css style).

<Example>
  <ContextColorsExample client:load />
</Example>

<Example>
  <VariantExample client:load />
</Example>

<Callout type="info">
  Using context to add meaning only provides a visual indication, which isn't conveyed to users of
  assistive technologies such as screen readers. Ensure that information denoted by the context is
  either obvious from the content itself (e.g. the visible text), or is included through
  alternative means, such as additional text hidden with the `.visually-hidden` class.
</Callout>

## Card layout

Beyond styling the content within a card, Chassis includes a few options for laying out series of
cards.

### Card groups

`<CardGroup>` renders cards as a single, attached element with equal-width and equal-height
columns. `<CardGroup>` uses a container query to switch from stacked to a row once its container
reaches the small container breakpoint, so it must be wrapped in an element carrying
`.contains-inline` to establish that container context.

<Example>
  <CardGroupExample client:load />
</Example>

Card footers line up automatically within a card group.

<Example>
  <CardGroupFooterExample client:load />
</Example>

### Grid cards

The `Row` component's `cols` prop (with `responsive` for breakpoint overrides) controls how many
grid columns wrap around a set of cards per row. `cols={1}` lays the cards out on one column, and
`responsive={{ medium: { cols: 2 } }}` splits four cards into two per row from the medium
breakpoint up.

<Example>
  <GridCardsExample client:load />
</Example>

Changing `responsive={{ medium: { cols: 3 } }}` wraps the fourth card onto a second row.

<Example>
  <GridCardsThreeColExample client:load />
</Example>

Adding `.h-100` to each card gives every card in a row equal height; setting `$card-height: 100%`
in Sass applies equal heights by default.

<Example>
  <GridCardsEqualHeightExample client:load />
</Example>

Card footers line up automatically within an equal-height row, the same as inside a card group.

<Example>
  <GridCardsEqualHeightFooterExample client:load />
</Example>
