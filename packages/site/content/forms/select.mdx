## Overview

`CxSelect` is a styled wrapper around a native `<select>` element, applying the same `.form-input` class and shared label/help/validation-feedback wiring as other form leaves — see [Form Field]([[docsref:/forms/form-field]]) for the underlying pattern. Pass an `options` array for data-driven rendering — plain strings, or objects conforming to `CxSelectOptionDef` (`label`, `value`, `disabled`, `selected`) — or omit it and write native `<option>` elements directly as children instead. An object option with no `value` renders without a `value` attribute, so the browser falls back to its text content.

## As a form field

Pass `label` / `help` / `invalid` / `invalidFeedback` / `valid` / `validFeedback` directly to `CxSelect` to render it together with an associated `CxFormLabel`, `CxFormHelp`, and `CxFormFeedback`, already wired up via `aria-describedby` and `aria-invalid` — see [Form Field]([[docsref:/forms/form-field]]) instead when a control needs to be grouped with companion content under one label.

## Native options

Omit the `options` prop and write native `<option>` elements directly as children when the list doesn't need to be data-driven — every attribute a plain `<option>` supports (`value`, `disabled`, `selected`, etc.) works exactly as it would outside `CxSelect`.

## Sizing

Set the `size` prop to `small` or `large` to change the control's padding, typography, and border radius — matching same-sized [Text Input]([[docsref:/forms/text-input]]) controls alongside it.

## Disabled

Add the `disabled` boolean attribute to give the control a muted color. Browsers also remove disabled controls from the tab order and from form submission automatically.

## Multiple selection

Set the `multiple` boolean prop to allow more than one option to be selected at once — pass `value` as a string array to control the selection from state, or see [Default selection](#default-selection) below for setting more than one option selected upfront without controlling `value` at all.

## Select size

The native `size` attribute — how many options show without scrolling, distinct from the small/large `size` prop above — is exposed as `htmlSize` instead, since `CxSelectProps` omits the native `size` attribute from its own type to avoid a name clash with the visual `size` prop.

  <SelectSizeExample client:load />

## Default selection

Mark one or more `options` entries `selected: true` to set the initial value without passing `value`/`defaultValue` directly — it's resolved into the select's own `defaultValue` internally, so it's ignored whenever `value`/`defaultValue` is also set. Mark more than one entry `selected` only when `multiple` is also set; otherwise, matching native `<select>` behavior, only the last `selected` entry wins (and a console warning flags the mistake in development).

<Example class="vstack gap-medium">
  <DefaultSelectionExample client:load />
</Example>

## Controlled value

Pass `value` and `onChange` to control the selected option from external state. Unlike [Text Input]([[docsref:/forms/text-input]]), `onChange` here isn't normalized to hand back the new value directly — it receives the native change event, the same as passing `onChange` to a plain `<select>`.
