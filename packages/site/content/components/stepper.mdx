## Overview

A stepper communicates progress through a sequence of discrete stages, rendered as an ordered
list by default. Each step carries one of three implicit states — past, current, or next —
derived entirely from which item carries `active`; there's no need to set a status on every
other step individually.

## Data-driven usage

Pass an `items` array to render steps from data. Mark the current step with `active` — items
before it render as completed, items after it as upcoming.

## Horizontal layout

Set `layout="horizontal"` to lay out steps side-by-side instead of stacking them vertically. The
connecting track and status indicator realign automatically for the row orientation.

### Responsive variants

Pass a breakpoint-prefixed value — `small:horizontal` through `2xlarge:horizontal` — to switch
from vertical to horizontal only from that breakpoint up. The stepper needs a parent carrying the
`.contains-inline` utility class, since the modifier switches layout through a container query
rather than a viewport media query.

## Interactive steps

Render each step as a link or button when it should navigate to another page or trigger an
in-page action — set `component="a"` (with `href`) or `component="button"` on `<StepperItem>`, or
`href` on a data-driven item definition. Because `<a>`/`<button>` elements aren't valid children of
an `<ol>`, `<Stepper>` automatically renders its root as a `<div>` instead whenever a step is
interactive — pass `component` explicitly if you need to override that.

## Accessibility

The active step should carry `aria-current="step"` so its position is conveyed to assistive
technology beyond color and layout alone — `<StepperItem active>` and a data-driven item with
`active: true` set this automatically. Interactive steppers built from links or buttons
additionally need a visually hidden prefix (such as "Current step: ") on the active item's label,
since a pseudo-element counter and color alone aren't reliably announced by screen readers.

Wrap an interactive stepper in a `<nav>` element with a descriptive `aria-label` (such as
`"Progress"`) to expose the sequence as a landmark for screen reader navigation. The default,
list-based stepper doesn't need this wrapper — an `<ol>`/`<li>` structure already carries native
list semantics.

See the
[ARIA `aria-current` specification](https://www.w3.org/TR/wai-aria-1.2/#aria-current) and the
[WAI-ARIA Authoring Practices Guide](https://www.w3.org/WAI/ARIA/apg/) for further guidance.
