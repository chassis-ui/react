# `chassis-react-site`

The Astro docs site for `@chassis-ui/react`, published at chassis-ui.com/react. It consumes the
library as `workspace:*`, so a page always reflects the in-repo library, and a broken build in
`packages/react` breaks the site.

## Content

- Read [`WRITING.md`](WRITING.md) before writing or editing any `.mdx` doc: voice, section order,
  the shortcodes, and the `## Scope`/`## Accessibility`/`## API` conventions.
- Every component page lives flat under `content/components/`, including the form and layout
  pages; the `Form Controls`/`Form Layout`/`Layout` groups of `data/sidebar.yml` are navigation
  only, not folders.
- A new page under `content/` must also get a `title:` entry in `data/sidebar.yml`, or it is
  reachable by URL only.
- `content/api/*.json` is generated by `pnpm react:generate` at the root, never hand-edited; a
  stale file shows stale props in `<PropTable>` without a warning.
- Live examples are React components under `examples/components/<component>/` and
  `examples/hooks/`, rendered by `<Example>` and shown as source verbatim, so the raw file is what
  readers see.

## Site mechanics

- `chassisDocs()` (`@chassis-ui/docs/integration`, `astro.config.ts`) auto-imports the package's
  shortcodes and everything in `src/components/shortcodes/` into every `.mdx` file; a same-named
  local file (`Example.astro`) replaces the package's, and the package's `Icon` is excluded
  because it collides with the library's. Components used in an example are still imported
  explicitly.
- A `[[docsref:/path]]` to a page that wasn't built and an unknown key in `config.yml` each fail
  the build. `UPGRADING.md` of `@chassis-ui/docs` is the contract for the integration.
- Read `src/libs/remark.ts` before adding a shortcode or custom directive: this site's own remark
  plugins run after the package's and decide how `<Example>` children are parsed.
- `config.yml`'s `title` stays short (`Chassis - React`): the shared `Head` appends it to every
  page's own title and html-validate caps a `<title>` at 70 characters. The home page is titled
  `title · subtitle` of `config.yml`, so the two together stay under 70 as well.

## Build and checks

- `pnpm lint:html` and `pnpm lint:vnu` run the `chassis-docs html-validate` and `chassis-docs vnu`
  commands over the built `_site/`, with this site's exceptions in `html-validate.json` and
  `vnu-filters.txt`: markup React and react-aria write on purpose, such as `spellCheck` in
  camelCase, ids from `useId` and explicit roles on native elements. Fix a new finding in the
  example or the component; add an exception only for markup that is correct (RD10 in
  [`DECISIONS.md`](../../DECISIONS.md)).
- `pnpm --filter chassis-react-site build` alone builds against whatever `content/api/` and
  `vendor/assets` are on disk; a representative build is the root `pnpm site:setup` then
  `pnpm site:build`.
