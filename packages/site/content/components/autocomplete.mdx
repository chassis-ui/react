## Overview

`Autocomplete` is chassis-css's button-trigger combobox — a display-only toggle that opens a panel containing its own search field, rather than a text input that's itself the trigger. That's the difference from [Combobox]([[docsref:/components/combobox]]): there, the text input is the combobox; here, the toggle just opens one. Compose an `AutocompleteItem` per option, each identified by an `id`, optionally grouped with `AutocompleteGroup`. Pass `placeholder` for the toggle's empty-state text and `searchPlaceholder` for the search field inside the panel.

## Multiple selection

Set `multiple` to allow more than one option to be selected. The toggle shows the single selection's label, or an "N selected" count once more than one is picked, and the panel stays open after each selection so more can be picked. `Backspace` in the empty search field removes the last selected option.

## As a form field

Pass `label`/`help` to wrap the autocomplete in a `.form-field` with an associated `FormLabel` and `FormHelp`. Pass `name` to have `Autocomplete` create and manage hidden `<input>`s for native form submission — one in single-select mode, one per selected key in `multiple` mode.

## Controlled selection

Pass `value`/`onChange` to control the selection directly — an array when `multiple` is set, a single id otherwise. Omit them (use `defaultValue` instead) to let `Autocomplete` manage selection internally.

## Accessibility

Opening the panel moves focus to the search field; closing it — via Escape, a selection, or an outside click — returns focus to the toggle. The toggle renders as a `<div role="button">` rather than a native `<button>`: an earlier version rendered removable chips for each selection directly inside it, which failed an automated accessibility check for nesting interactive controls inside a button, so selections now render as plain text instead and the non-native trigger stays in place.

## Scope

- **No typeahead while closed.** Unlike a native `<select>`, there's no way to jump to an option by typing a letter before opening the panel — the search field only exists once the toggle has been activated.
- **No async filtering.** Matching happens entirely client-side against the options already passed as `children`/`items`; there's no controlled input value or `onInputChange` callback to drive a server-side search.
