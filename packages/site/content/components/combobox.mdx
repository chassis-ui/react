## Overview

`Combobox` combines a text input with a filterable list of options — type to narrow the list, arrow keys to move through it, Enter to select. It replaces hand-wiring a `Menu` to a text input with real combobox semantics: `role="combobox"` on the input, `role="listbox"`/`role="option"` on the list, and `aria-expanded`/`aria-controls`/`aria-activedescendant` kept in sync automatically. For a display-only toggle that opens the option list instead of typing directly into it, see [Autocomplete]([[docsref:/components/autocomplete]]).

Compose a `ComboboxItem` per option, each identified by an `id`.

## Data-driven items

Pass an `items` array instead of composing children to build the option list from data. A `'header'` entry starts a group that every following item joins until the next header or the end of the array; `items` wins over `children` when both are set.

## As a form field

Pass `label`/`help` to wrap the combobox in a `.form-field` with an associated `FormLabel` and `FormHelp`. Pass `name` to have `Combobox` create and manage a hidden `<input>` for native form submission — its value stays in sync with the selection.

## Controlled selection

Pass `value`/`onChange` to `Combobox` to control the selected option yourself. Omit them (use `defaultValue` instead) to let `Combobox` manage selection internally.

## Scope

This is the single-select, type-to-filter combobox — the strong-fit case for React Aria's combobox hooks, and the most common combobox pattern. Two related patterns live in other components instead:

- **A button-trigger toggle with its own search field** — see [Autocomplete]([[docsref:/components/autocomplete]]).
- **Multiple selection** — also [Autocomplete]([[docsref:/components/autocomplete]]), via its `multiple` prop, built on the same button-trigger composition.

**No async filtering.** Matching happens entirely client-side against the options already passed as `children`/`items`; there's no controlled input value or `onInputChange` callback to drive a server-side search.
